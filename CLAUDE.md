# Workflow

- Haz commits atómicos (un cambio lógico por commit).
- Haz push periódicamente, no necesariamente después de cada commit.
- Anota las decisiones de ingeniería importantes (arquitectura, elección de
  librerías, cambios respecto a PLAN.md, bloqueos y su resolución) como
  entradas de diario en `journal/`, un fichero markdown por entrada
  (`journal/YYYY-MM-DD-slug.md`). No es un changelog de cada cambio: solo
  decisiones que alguien revisando el proyecto necesitaría entender el
  "por qué".
